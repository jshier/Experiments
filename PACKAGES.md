# PACKAGES.md

What each package holds, in detail (moved out of AGENTS.md on 2026-11-25; AGENTS.md has the short table).

## Repository

Independent experiments, each its own SwiftPM package (no root package). The performance ones:

| Project | What | Record |
|---|---|---|
| `Bytes` | Span-based binary reading/writing (`BytesReader`/`BytesWriter` at bit granularity, `AlignedBytesReader`/`AlignedBytesWriter` for whole bytes, `BigEndianBytesReader`/`LittleEndianBytesReader` and writers for integers by type, named bit fields (`BitFlag`, `BitField`, `BitPattern`), records (`BinaryParsable`), `BitBuffer`/`BitWriter` for entropy coding, `ByteBuffer`, `ByteLanes` SIMD scanning and NEON shuffles via the `CBytesNEON` C target, `ByteBlock`: 64 bytes tested into one 64-bit mask for structural indexes), CRC-32 and Adler-32 (`RunningChecksum`), byte pipelines (`ByteTransform`), `LentBytes`/`LentMutableSpan`/`LentMutableBytes` for parallel work (input, memory read and written in place, output capacity), `RawStorage` (memory made once, pages given back between uses); `BytesBase64` (vectorized Base64 encoding and decoding: NEON `tbl`/`tbx` block kernels, auto-vectorized `ld3`/`st4` group kernels; whitespace-skipping decoding for PEM; was the `Base64` package, record `RESULTS-base64.md`); `BytesAsync` (async buffers, pipelines, `offloaded(to:)`/`concurrently()` stages; the waiting primitives Disk, NativeAEA, and NativeZip share, on the standard library's noncopyable `Continuation`: `wait(in:_:)`, `WaiterQueue`, `AsyncLimiter` (`withPermit`), `AsyncIndexPool` (closable, late activation), `AsyncLatch`, `AsyncQueue`, `AsyncHandoff`; and `RelaxedCounter`, `RelaxedCounters` (N counters, one allocation), `MonotonicClock`, `withPriority`); `BytesMacros` (`@BitFields`, `@BinaryRecord`); `BytesFoundation` (`Data` with spans); the codecs are the `BytesCompression` package (below); `BytesCrypto` (ChaCha20-Poly1305, AES-GCM and AES-CTR on ARM's AES/PMULL instructions via the `CBytesCrypto` C target, SHA-1/256/384/512, HMAC, PBKDF2, HKDF, scrypt, TLS 1.3's key schedule and record layer, sealing in parallel; P-256 and P-384 ECDSA verification and ECDH (keys and signatures in DER and PEM, both ways), HPKE; RSA PKCS #1 v1.5 verification (1024–4096-bit keys, SHA-1/256/384/512); DER, PEM, and X.509 parsing, and certificate signatures (`isSigned(by:)`, RSA and ECDSA)) | `Benchmarks/RESULTS.md` (and its `RESULTS-*.md`; compression's record until 2026-11-23) |
| `BytesCompression` | The codecs, on Bytes (moved out of the Bytes package on 2026-11-23, module unchanged): `BytesCompression` (DEFLATE/zlib/gzip and Brotli, both directions, and Deflate64 decoding (`DeflateDecoder(variant:)`, and decoding into a caller's buffer after its history); Zstandard decoding, and encoding at libzstd's levels 1–4 (`ZstdEncoder`: its frames byte for byte, one call or streamed, `Parameters.httpWindowLog`; record `Benchmarks/RESULTS-zstd-encoder.md`), XXH64; LZMA, LZMA2, and `.xz` decoding, whole or streaming (`LZMADecoder`, `XZDecoder`; one `Decompressor` over every format, `DecompressionFormat`, for clients that choose at run time), CRC-64 (carry-less multiply via the `CBytesCompression` C target); bzip2 decoding, whole or streaming; Apple's LZFSE, LZVN, LZ4, LZBITMAP, and LZRAVEN decoding, and LZFSE, LZVN, and LZBITMAP encoding (all three byte for byte as Compression's; the open references' parse as an option)); the layers above the codecs that NativeZip, NativeAEA, Disk, and HTTPBytes share (2026-11-23, ARCHITECTURE.md): containers' identifiers mapped to `DecompressionFormat` (`init?(zipMethod:uncompressedSize:)`, `LZMAProperties(zipHeader:)` and `.zipLZMA`, `init?(aeaSegment:)`, `init?(pbzBlock:)` with `AppleArchiveCompression`'s letters), `CompressionFormat` and `Compressor` (one encoder chosen at run time: Disk's APFS chunks, HTTP's content coding), `ChunkedDecompressor` (a stream in ≤ 1 MiB chunks into two alternating buffers, borrowed or staged input: ZIP's pump), `PBZ` (`pbz`/pbzx framing, `PBZError`); `BytesCompressionAsync` (the parallel codecs' `async` entry points: `compressAll(_:into:on:)`, `compressAllConcurrently`, `decompressAll(_:into:on:)`; and `ParallelBlockDecoder<Stage>`, the one engine for independent blocks (AEA segments, `pbz` blocks from a file or an upstream source, plain slices), ordered output, `BlockBufferPool`, a per-block `BlockStage` hook for the client's reading, MACs, and decryption, errors composed through `BlockDecodingFailure`; inlinable, so clients specialize it); `BytesReferenceCodecs` (zlib's and Compression's buffer APIs as references, for tests and benchmarks). Traits mirror Bytes' (`NEONShuffle`, `HardwareCRC`, `HardwareCrypto`, `Portable`) and pass on to it; `bench` runs the three builds. `CompressionBenchmarks` keeps BytesCrypto's rows (ciphers, ECC, RSA, TLS, pipelines) and the reference libraries (`CLibDeflate`, `CBrotli`, `CZstd`, `CLZMA`, `CBZip2`) | `RESULTS.md`, `Benchmarks/RESULTS-*.md` |
| `MQTT` | MQTT 5 packets on Bytes: `MQTTFrame` (zero-copy header + body), per-type `init(parsing:)`/`write(to:)` | `Benchmarks/RESULTS.md` |
| `SocketStream` (was `MQTTSocketStream`) | MQTT over sockets with a PR toolchain's I/O interfaces, optionally compressed and TLS-encrypted through Bytes pipelines; concurrency hops | `RESULTS.md` |
| `NativeZipArchive` | ZIP: stored, DEFLATE, Deflate64, bzip2, LZMA, xz, Zstandard, every one decoded by BytesCompression's streaming decoders through its `ChunkedDecompressor`, methods mapped by `DecompressionFormat(zipMethod:…)` (no zlib, Compression, or libbz2 in the library or `nunzip`; tests and benchmarks use them as references); ZipCrypto and WinZip AES (on BytesCrypto, decrypted as streamed into the pump's staged input); `ZipExtractor` (many archives, one worker pool, an optional quarantine for everything extracted); `ZipExtractionOptions` (Disk's Boolean names: `restoresTimestamps`, `keepsSpecialBits`, …); `nunzip` (Info-ZIP unzip's options); typed `throws(ZipError)` throughout, composing what it meets (`.decoding(BytesError, entry)`, `.disk(DiskError)`, `.cancelled`; `ZipContentsError<Failure>` for a reading body's own errors) | `Benchmarks/RESULTS.md` |
| `NativeAEA` | Apple Encrypted Archives (`.aea`: Xcode's, iOS IPSWs' disk images) and Apple Archives (`.aar`, plain or `pbz`): all six AEA profiles (signatures and certificate chains, symmetric, ECDH, and scrypt keys, IPSWs' WKMS keys by HPKE), all on BytesCrypto; segments and blocks decoded in parallel by BytesCompressionAsync's `ParallelBlockDecoder` (AEA's MAC, decryption, and checksum in its `AEASegmentStage`; `AppleArchiveCompression`, `PBZ`, and `BlockBufferPool` are BytesCompression's) (no Compression framework or Foundation parser anywhere: WKMS's JSON has its own reader on Bytes; every file read through Disk's `InputFile`); the Apple Archive stream walked with no copies; files written as `aa extract` writes them, byte for byte (APFS `decmpfs` compression with BytesCompression's encoders, extended attributes, ACLs, hard links, FIFOs, quarantine) by writers outside a file system semaphore; decryption to a file, with ranges; Xcode's `.xip` too (XAR TOC, RSA signature and chain to Apple Root CA on BytesCrypto, pbzx blocks of xz, the cpio stream walked into the same extractor, files stored as `xip --expand` stores them); `ArchiveKind` (a file's format by its first bytes, then its extension: `.zip` too); `AEAExtractionOptions.disk` (Disk's `ExtractionSettings` itself: writers, width, progress, timings); `nunarchiver` (was `unaea`); archives hold their file open until `close()`; a wrong key or password is `AEAError.incorrectKey`; FORMAT.md documents the formats, ARCHITECTURE.md the pipeline and its threads | `RESULTS.md`, `XIP-REPORT.md` |
| `Disk` | Writing extracted trees, shared by NativeAEA and NativeZip: `EntryPath` (validated relative paths), `Destination` (contained creation with `O_NOFOLLOW_ANY`/`O_RESOLVE_BENEATH`, staging then `publish`/`publishUnwrapped` (Archive Utility's naming)/`discard`), `FileWriter` (one thread, no allocations; `package`, for Disk's tests and benchmarks), `Extraction.run(into:source:settings:_:)` with a `Planner` and `ContentSource`/`PieceSource` (writers outside a file-system limiter, large files in pieces; `ExtractionReport`'s timings keyed by `ExtractionPhase` and `WriterWork`), APFS `decmpfs` storage as `aa extract` and `xip --expand` store it, metadata in one `fsetattrlist`, quarantine, hard and symbolic links; `ExtractionProgress` (relaxed per-writer counters, polled; `read()` gives the entry-weighted fraction that never goes back); `Destination.reopened(with:)` (clients extract into the caller's `Destination`); errors composed, not boxed (`ContentSource.Failure`, `EntryError<Failure>` (`.disk`/`.source`), `ExtractionError<PlanFailure, SourceFailure>`); `MappedFile` (the archive being read; a private copy on volumes where a truncated mapping faults: FAT, exFAT), `InputFile` (reads at offsets, small whole files such as keys), and `OutputFile` (one file at the caller's path); descriptors closed explicitly (`close()` on every owner; `OwnedDescriptor`, `DescriptorSlot`; `deinit` only audits: `DescriptorAudit`, `DiskLifetimes` in DiskTestSupport); `unquarantinedItems` (volumes without extended attributes); a `SyscallCounting` trait for the benchmarks, and debug-only fault injection (`SyscallFaults`) | `RESULTS.md`, `ARCHITECTURE.md` |
| `HTTPBytes` | HTTP/1.1, HTTP/2, HTTP/3 framing and fields on Bytes, no allocations per message: `HTTP1` (streaming request/response head parsers yielding the start line and each field as views: a structural index of 64-byte blocks walked with ctz, 2.1–2.8x as fast as picohttpparser/llhttp; framing per RFC 9112 §6.3, chunked cursor handing out slices, head writers), `HTTP2` (frames, HPACK with a 14-bit multi-symbol Huffman decoder, field-section validation), `HTTP3` (QUIC varints, frames, QPACK with blocked streams), core `HTTPBytes` (`HTTPFieldName` perfect hash over ~120 names, `HTTPFieldStore`, methods, statuses, Structured Fields RFC 9651, `Priority`, request-target validation and components; field values as views: `HTTPDate` (35x Foundation's parser), media types and `Accept` negotiation, ranges, entity tags and RFC 9110 §13.2.2 preconditions, `Cache-Control`, `Host`, credentials and challenges, `Content-Disposition` with RFC 8187, cookies, `Forwarded`), `HTTPPayload` (content codings on BytesCompression, zstd encoding included; `HTTPBodyDecoder`: framing and codings in one stage; chunked stages `HTTP1Dechunker`/`HTTP1Chunker` in HTTP1), `HTTPBytesHTTPTypes` (swift-http-types conversions). Benchmarks are their own package (`HTTPBytes/Benchmarks`: C references picohttpparser, llhttp, cursed-http, ls-hpack, ls-qpack built from TestData); conformance suites from llhttp, Go, h11, httparse, http-parser, picohttpparser, cursed-http, HTTP Garden, PortSwigger's DesyncBox, h2o's corpus | `RESULTS.md`, `PLAN.md`, `WRITEUP.md` |
| `Nunarchiver` | macOS app (TCA26, Xcode project) replacing Archive Utility for `.zip`, `.aea`, `.aar`, `.xip`: expands next to the archive through Disk's staging as Archive Utility does (compared item by item), progress window polling `ExtractionProgress` (throughput in GB/s from the polled bytes), passwords and keys asked for in the row. Build with its `build.sh` (shared scheme, coverage off) | — |
| `BinaryParsingComparison` | Bytes vs swift-binary-parsing | `RESULTS.md` |
| `NativeISO8601`, `*Benchmark` | Smaller benchmarks | READMEs |
